# 文书协作规则

版本 1.30.0，独立工具适用的写作条款。

## 文书辅导：早期草稿


- `essay-early-stage-detail`：早期阶段的目标不是成稿，而是帮助学生补充关键细节、情节、困难和转折；在素材充分后再讨论如何改得更好。
- `essay-story-first`：先找到叙事主线和因果关系，再检查信息缺口。不要先给一张“日期、数字、动作”的完整性清单。
- `essay-detail-function`：不能只说“增加细节”；要指出需要补充什么场景，以及这段场景在故事里承担什么作用。
- `essay-causal-spine`：优先寻找“动机或目标 → 现实障碍 → 关键判断 → 主动行动或迭代 → 更大意义”的因果链。它是分析视角，不是强制每篇文章使用同一种段落模板。
- `essay-comment-source-anchor`：顾问问题与批注紧跟对应正文，直接点明来源中已知的人物、地点、动作或原文片段。顾问文字不用「一个」「一次」「某个」「最近一次」「哪一年」「哪一句」等空槽表达。该规则不机械改写学生原文。

## 文书辅导：微信反馈


- `essay-wechat-brief`：每篇只列两到三个最重要的反馈，使用可直接转发的文字，不写长篇总评。

## 文书辅导：完整 Clean Draft 交付


- `essay-clean-draft-near-word-limit`：所有文书修改先逐篇核实官方上限及计数单位。最终修改稿、完整成稿和 clean draft 的正文必须位于上限减15至上限之间，且不得超限。Common App 650词题目使用635-650词，UC PIQ 350词题目使用335-350词。Prompt、标题、批注和修改说明不计入正文。2026-10-09业务负责人明确确认，状态为`confirmed`，替代2026-09-05的上限减20规则。
- `essay-clean-draft-no-padding`：字数下限不能通过空话、重复或虚构事实填充。现有素材不足以安全达到下限时，不交付偏短稿，改用中文说明缺少的具体内容。
- `essay-clean-draft-format`：clean draft 文件只保留完整 Prompt 和正文，不放评分、字数、状态、批注、追问、占位符、修改说明、页眉或页脚。
- `essay-clean-draft-stage-override`：本节适用于所有整篇文书的最终修改交付，程序使用`clean-draft`阶段，不因文件名含“工作稿”而降低要求。内部未完成版本、局部片段和明确的素材讨论继续使用早期草稿规则，不能把偏短正文当作完整修改稿交付。上限尚未核实或素材不足时，先说明准确缺口。

## 使用顺序

1. 当前任务中的明确要求优先于本文件。
2. `task` 规则优先于 `domain`，`domain` 优先于 `project`，`project` 优先于 `global`。
3. 单次反馈先作为候选；只有业务负责人明确确认后，才能进入本文件并影响长期协作。
4. 两条已确认规则冲突时暂停套用，由业务负责人判断；不得自行选择更顺手的一条。
5. 新反馈可以替代旧反馈，但必须保留替代关系，不能静默删除历史。
